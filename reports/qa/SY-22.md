# SY-22 QA Report

## Scope

SY-22 — DeepSeek V4 Pro Reasoning Model Support. Adds a first-class reasoning channel through the entire Synapse stack: `Message.reasoning_content`, `StreamEvent::ReasoningDelta`, wire-format extensions in `openai_compat`, reasoning-aware DeepSeek factory with effort auto-escalation, agent loop preservation of reasoning on tool-call turns, SQLite persistence, distinct REPL rendering, Telegram `<blockquote>` rendering, and a config-level visibility toggle. Also includes review fix RF1 (Telegram `show_reasoning` privacy regression when `[telegram]` section is absent).

## Risk Zones

- **Tool-call history rule correctness** — DeepSeek requires `reasoning_content` on every subsequent API call when the assistant turn had tool calls. The logic lives in `build_api_messages` and is gated on `tool_calls.is_some() && reasoning_content.is_some()`. Covered by unit and integration tests, but can only be fully validated against the live DeepSeek V4 Pro API (no mock can catch protocol-level 400 errors).
- **`max_tokens` floor for `"max"` effort** — The PRD notes `max_tokens = 4096` may truncate reasoning output. No automatic floor was added (deferred). Deployments that upgrade to V4 Pro without bumping `max_tokens` may see truncated answers. Documented in README but not enforced.
- **`REASONING_MODELS` list drift** — As DeepSeek releases more reasoning variants (e.g. `deepseek-v4-pro-max`), `REASONING_MODELS` in `deepseek.rs` must be updated. Single constant with a mirror in `docs/research/SY-22-deepseek-v4-pro.md`, but no automated freshness check.
- **Privacy regression if `is_some_and` reverted** — RF1 fixed the Telegram privacy default from `is_none_or` to `is_some_and`. The regression test `test_telegram_reasoning_hidden_when_telegram_section_absent` guards this, but the test exercises `is_some_and` indirectly through the config resolver rather than calling `handle_message` end-to-end (Telegram handler is hard to integration-test without a mock bot). The gap is explicitly noted in the tasklist RF1 acceptance criterion.
- **REPL DIM style terminal compatibility** — `Modifier::DIM | Modifier::ITALIC` may render invisibly on some terminal themes (low contrast). No user-configurable style override is provided in SY-22 (deferred to follow-up).
- **One-shot CLI `is_none_or` for `[cli]` absent** — CLI uses `is_none_or(|c| c.show_reasoning)` so a missing `[cli]` section defaults to showing reasoning on stderr. This is the correct developer default per PRD Decision 3, and is the inverse of the Telegram decision, so it does not introduce an inconsistency — but it is worth noting during review that the two paths intentionally use opposite helper methods.

## Verdict

**release**

All 335 automated tests (synapse-core: 208, synapse-cli: 42, synapse-telegram: 85) pass. `cargo clippy -- -D warnings` is clean. Every acceptance criterion for tasks 22.1 – 22.8 and review fix RF1 is satisfied. The critical privacy regression (RF1) is fixed via `is_some_and` and covered by a dedicated regression test. The backwards-compatibility invariant (non-reasoning providers and `deepseek-chat` produce byte-identical wire format) is confirmed by the `test_request_omits_thinking_when_reasoning_none` regression guard. The two items remaining are non-blocking: the `max_tokens` floor for `"max"` effort is documented as a recommendation, and the `REASONING_MODELS` list staleness risk is managed by a single well-documented constant. No gaps requiring a follow-up ticket before release were identified.
