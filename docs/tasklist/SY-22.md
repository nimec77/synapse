# SY-22: DeepSeek V4 Pro Reasoning Model Support

**Status:** REVIEW_OK

## Context

SY-22 adds DeepSeek V4 Pro (reasoning model) support to Synapse by introducing a first-class reasoning channel through the entire stack: `Message.reasoning_content`, `StreamEvent::ReasoningDelta`, wire-format extensions in `openai_compat`, a reasoning-aware DeepSeek factory, agent loop preservation of reasoning on tool-call turns, SQLite persistence, and distinct rendering in REPL and Telegram. Derived from `docs/prd/SY-22.prd.md` and `docs/plan/SY-22.md`.

## Review Fixes

- [x] **RF1: Telegram `show_reasoning` defaults to `true` when `[telegram]` is absent (privacy regression)**
  - `synapse-telegram/src/handlers.rs:189` uses `config.telegram.as_ref().is_none_or(|t| t.show_reasoning)`. `is_none_or` returns `true` when `telegram` is `None`, so a deployment that supplies the bot token via `TELEGRAM_BOT_TOKEN` env var and omits the `[telegram]` section entirely will emit reasoning `<blockquote>`s by default — violating PRD Goal 7 ("in Telegram, hide reasoning by default (privacy: messages can be screenshotted/forwarded)"), Constraint 4 ("backwards compatibility ... existing config files still parse and run unchanged"), and Decision 3 ("Telegram: hide by default (`telegram.show_reasoning = false`)").
  - The CLI counterpart in `synapse-cli/src/repl.rs:89` and `synapse-cli/src/main.rs:148` is correct — CLI default is `true`, so `is_none_or` matches the CLI semantics. Only the Telegram path needs the inversion.
  - Fix: change to `is_some_and(|t| t.show_reasoning)` so a missing `[telegram]` section defaults to `false` (privacy-preserving), matching the `TelegramConfig::default()` impl which already sets `show_reasoning: false`.
  - Add a regression test that constructs a `Config` with `telegram: None` (or builds the body via the production resolver) and asserts the outgoing body does not contain `<blockquote>` or the fixture reasoning text. The current test helper `build_body` accepts the boolean directly and does not exercise the config-resolution path, which is why this slipped through.
  - **Acceptance:** With `config.telegram = None` and a fixture `Message` carrying `reasoning_content`, the body produced by `handle_message`'s render block contains neither `<blockquote>` nor the reasoning text. New regression test (e.g. `test_telegram_reasoning_hidden_when_telegram_section_absent`) exercises the production resolver and passes. `cargo fmt --check && cargo clippy -- -D warnings && cargo test -p synapse-telegram` is green.
