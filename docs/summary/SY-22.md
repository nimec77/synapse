# SY-22: DeepSeek V4 Pro Reasoning Model Support

**Shipped:** 2026-05-10
**Version:** pending (next minor bump)

## What Shipped

Synapse now supports DeepSeek V4 Pro, a chain-of-thought reasoning model. Setting `model = "deepseek-v4-pro"` in `config.toml` automatically enables thinking mode, which causes the model to emit step-by-step reasoning alongside its final answer. The reasoning channel is threaded through the entire stack — from the API wire format through the agent loop, SQLite persistence, REPL rendering, and Telegram output — while existing non-reasoning models (`deepseek-chat`, OpenAI, Anthropic) are completely unaffected and produce byte-identical request bodies to before SY-22.

## How It Works

**Core types** (`synapse-core`):
- `Message` gains `pub reasoning_content: Option<String>` and a `with_reasoning(...)` builder. Populated on assistant messages from reasoning models.
- `StreamEvent` gains a `ReasoningDelta(String)` variant (enum is now `#[non_exhaustive]` for future Anthropic/OpenAI reasoning support).

**Wire format** (`synapse-core/src/provider/openai_compat/`):
- `ApiRequest` and `StreamingApiRequest` gain optional `thinking: Option<ThinkingConfig>` and `reasoning_effort: Option<String>` fields (skipped via `serde(skip_serializing_if)` when absent).
- `ApiMessage`, `ChoiceMessage`, and `StreamDelta` gain `reasoning_content: Option<String>`.
- `OpenAiCompatProvider` gains an optional `ReasoningSettings` field and a `with_reasoning(...)` builder. When set, every outbound request includes `{"thinking": {"type": "enabled"}}` and the configured effort level.
- `build_api_messages` replays `reasoning_content` on outbound assistant turns only when `tool_calls.is_some()` (DeepSeek's mandatory history rule); text-only turns drop it to save tokens.

**DeepSeek provider and factory** (`synapse-core/src/provider/deepseek.rs`, `factory.rs`):
- `REASONING_MODELS = &["deepseek-v4-pro"]` constant; `is_reasoning_model(model)` helper.
- `DeepSeekProvider::new` accepts `reasoning_effort: Option<String>` and activates thinking mode only for reasoning-capable models.
- Factory resolves effective effort: explicit config value > `"max"` when MCP tools are configured (auto-escalation) > `"high"` default.

**Config** (`synapse-core/src/config.rs`):
- `Config.reasoning_effort: Option<String>` — effort override for DeepSeek reasoning models.
- `CliConfig { show_reasoning: bool }` (default `true`) — controls REPL and one-shot stderr output.
- `TelegramConfig.show_reasoning: bool` (default `false`, privacy-preserving).

**Agent loop** (`synapse-core/src/agent.rs`):
- `Agent::stream` and `stream_owned` yield `ReasoningDelta` before `TextDelta` when the final response carries reasoning.
- `build_messages()` clones messages without stripping `reasoning_content`, so the tool-call history rule is automatically satisfied.

**Storage** (`synapse-core/`):
- Migration `20260510_004_add_reasoning_content.sql` adds a nullable `reasoning_content TEXT` column to the `messages` table.
- `StoredMessage` gains `pub reasoning_content: Option<String>` and a `with_reasoning(...)` builder. Round-trips through SQLite so resumed sessions with previous tool calls still satisfy DeepSeek's protocol.

**REPL** (`synapse-cli/src/repl/`):
- `DisplayMessage` tracks a separate reasoning buffer. `ReasoningDelta` events populate it.
- `build_history_lines` renders reasoning in `Modifier::DIM | Modifier::ITALIC` style prefixed with `▎reasoning: ` above the final answer when `cli.show_reasoning = true`.
- One-shot mode routes `ReasoningDelta` content to stderr (keeping stdout clean for piping).

**Telegram** (`synapse-telegram/src/handlers.rs`):
- `TELEGRAM_REASONING_PREVIEW_MAX_CHARS = 1500` constant.
- Reasoning is persisted to SQLite unconditionally. Display is gated on `telegram.show_reasoning`: when `true`, a `<blockquote>{escaped preview}</blockquote>` block is prepended to the first chunk; when `false` (default), reasoning is silently dropped from outgoing messages.
- RF1 fix: a missing `[telegram]` section now correctly defaults to hiding reasoning (`is_some_and` instead of `is_none_or`) — the privacy-preserving default is maintained even when no `[telegram]` config block is present.

**`MockProvider`** gains `with_reasoning_response(content, reasoning)` for agent integration tests.

## Decisions

- **`ReasoningDelta` routing in one-shot CLI** — Routed to stderr (not stdout) so that `synapse "..." | jq` piped use cases remain clean. `cli.show_reasoning = false` silences both channels.
- **Tool-call history rule policy** — Drop `reasoning_content` on text-only turns; replay it on tool-call turns. This is DeepSeek-spec-exact with no config knob — the spec leaves no room for a toggle.
- **`[telegram]` absent defaults to hidden** — Uses `is_some_and(|t| t.show_reasoning)` so deployments that supply the bot token only via env var (no `[telegram]` block) never accidentally leak reasoning content.
- **`StreamEvent` marked `#[non_exhaustive]`** — Pre-1.0 is the right time; future Anthropic/OpenAI reasoning variants (proposed SY-23) can be added without a public-API breaking change.
- **Effort auto-escalation** — When MCP tools are configured and no explicit `reasoning_effort` is set, the factory resolves `"max"`. This mirrors documented best practice for agentic flows. A `tracing::info!` event with `auto_escalated = true` makes the choice observable.

## Follow-ups

- **Anthropic extended thinking (SY-23)** — `Message.reasoning_content` and `StreamEvent::ReasoningDelta` are already in place; only provider-level wire-format work remains. Deferred.
- **OpenAI o-series reasoning** — Same pattern; deferred.
- **`max_tokens` floor for `"max"` effort** — `max_tokens = 4096` (default) may truncate answers from long reasoning chains. Recommendation to use 8192+ is documented in README but no automatic floor was added. Revisit if truncation is reported in practice.
- **Per-chat Telegram `/reasoning` toggle** — Runtime per-chat visibility toggling with persistence deferred to a follow-up ticket. SY-22 is `config.toml`-driven only.
- **`REASONING_MODELS` freshness** — Single constant in `deepseek.rs` mirrored in the research note; must be updated when DeepSeek releases additional reasoning variants.
- **REPL style configurability** — `Modifier::DIM | Modifier::ITALIC` is a constant; users on low-contrast terminal themes may find it hard to read. Future polish: config-driven style.
