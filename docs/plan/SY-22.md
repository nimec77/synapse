# SY-22 Plan: DeepSeek V4 Pro Reasoning Model Support

**Ticket:** SY-22
**Status:** PLAN_APPROVED
**Date:** 2026-05-10

---

## Summary

SY-22 adds DeepSeek V4 Pro (reasoning model) support to Synapse. The work introduces a first-class **reasoning channel** through the entire stack:

- `Message.reasoning_content: Option<String>` (new field) round-trips through providers, the agent, SQLite, REPL, and Telegram.
- `StreamEvent::ReasoningDelta(String)` (new variant) lets streaming surfaces distinguish chain-of-thought from the final answer.
- The wire format gains optional `thinking: { "type": "enabled" }` and `reasoning_effort` request fields plus `reasoning_content` on the response/delta. These are gated to DeepSeek reasoning-capable models only — OpenAI and `deepseek-chat` send byte-identical payloads to today.
- Effort defaults to `"high"` and **auto-escalates to `"max"`** when MCP is configured and the user did not set `reasoning_effort` explicitly.
- The agent loop preserves `reasoning_content` on assistant messages so DeepSeek's tool-call history rule is honored automatically.
- The REPL renders reasoning in dim/italic above the answer (default on); Telegram hides reasoning by default and shows it as `<blockquote>` only when `telegram.show_reasoning = true` (privacy-preserving).
- A new SQLite migration adds a nullable `reasoning_content` column so resumed sessions still satisfy the protocol.

Eight scenarios from the PRD map 1:1 to eight implementation tasks (22.1 – 22.8). No deviations were detected against the current code; every gap is an additive extension.

## 2. API Contract

### 2.1 `Message`

```rust
// synapse-core/src/message.rs

#[derive(Debug, Clone, PartialEq)]
pub struct Message {
    pub role: Role,
    pub content: String,
    /// Tool calls requested by the assistant (Some when role == Assistant
    /// and the model invoked tools).
    pub tool_calls: Option<Vec<ToolCallData>>,
    /// Tool call ID this message responds to (Some when role == Tool).
    pub tool_call_id: Option<String>,
    /// Chain-of-thought emitted by reasoning-capable models (e.g.
    /// deepseek-v4-pro). Set on Assistant messages produced by
    /// reasoning models. MUST be replayed back to the API on every
    /// subsequent turn when the same assistant message also has
    /// tool_calls (DeepSeek thinking-mode requirement). Dropped from
    /// outbound history on text-only turns to save tokens.
    pub reasoning_content: Option<String>,
}

impl Message {
    pub fn new(role: Role, content: impl Into<String>) -> Self;
    pub fn tool_result(tool_call_id: impl Into<String>, content: impl Into<String>) -> Self;

    /// Builder: attach reasoning content to this message.
    pub fn with_reasoning(mut self, reasoning: impl Into<String>) -> Self;
}
```

`Message::new` and `Message::tool_result` initialize `reasoning_content: None`.

### 2.2 `StreamEvent`

```rust
// synapse-core/src/provider/streaming.rs

#[derive(Debug, Clone)]
#[non_exhaustive]
pub enum StreamEvent {
    /// Incremental fragment of the user-visible answer.
    TextDelta(String),
    /// Incremental fragment of chain-of-thought reasoning (DeepSeek V4 Pro
    /// and other reasoning models). Renderers should display this above /
    /// distinct from TextDelta.
    ReasoningDelta(String),

}
```

### 2.7 `factory::create_provider`

The factory resolves the effective reasoning effort:

```rust
fn resolve_reasoning_effort(config: &Config) -> (String, bool) {
    // Returns (effort, auto_escalated).
    if let Some(explicit) = config.reasoning_effort.as_ref() {
        (explicit.clone(), false)
    } else if config.mcp.is_some() {
        ("max".to_string(), true)
    } else {
        ("high".to_string(), false)
    }
}
```

For `provider == "deepseek"`:

```rust

DeepSeekProvider::new(api_key, model, max_tokens, Some(effort.0.clone()))
```

```rust
    effort = %effort.0,
    auto_escalated = effort.1,
```

For `provider != "deepseek"` AND `config.reasoning_effort.is_some()`:

### 2.11 `Agent::stream*` tools-present yield order

When `tools` are non-empty, `stream` and `stream_owned` already buffer tool iterations through `complete()` and yield only the final response. The contract becomes:

1. If `final_response.reasoning_content` is `Some(s)`, yield `StreamEvent::ReasoningDelta(s)`.
2. Yield `StreamEvent::TextDelta(final_response.content)`.
3. Yield `StreamEvent::Done`.

Streaming paths without tools delegate to `provider.stream(...)` unchanged — the provider already emits `ReasoningDelta` from `stream_sse`.

## 3. Data Flows

### 3.1 Outbound request — DeepSeek V4 Pro with reasoning

```
User -> Agent::complete(messages)
  -> DeepSeekProvider::complete(messages)
    -> OpenAiCompatProvider::complete(messages)
      -> build_api_messages(messages)
           // For each Assistant message:
           //   if msg.tool_calls.is_some() && msg.reasoning_content.is_some()
           //     -> ApiMessage.reasoning_content = Some(...)
           //   else
           //     -> drop reasoning_content (text-only turn)
      -> complete_request(ApiRequest {
            model: "deepseek-v4-pro",
            messages: [...],
            max_tokens,
            tools: Some([...]) | None,
            tool_choice: Some("auto") | None,
            thinking: Some(ThinkingConfig { kind: "enabled" }),  // gated on self.reasoning.is_some()
            reasoning_effort: Some("high"),                       // gated on self.reasoning.is_some()
         })
      -> POST https://api.deepseek.com/chat/completions
```

For `model == "deepseek-chat"` (no thinking mode), `self.reasoning` is `None`, so `thinking` and `reasoning_effort` are omitted by `skip_serializing_if`. **Byte-identical to pre-SY-22.**

### 3.2 Inbound non-streaming response

```
HTTP 200 -> ApiResponse {
  choices: [Choice {
    message: ChoiceMessage {
      content: Some("final answer"),
      reasoning_content: Some("let me think..."),
      tool_calls: None | Some([...]),
    }
  }]
}
  -> Message {
       role: Assistant,
       content: "final answer",
       reasoning_content: Some("let me think..."),
       tool_calls: ...,
       tool_call_id: None,
     }
  -> Agent appends to history -> next iteration sees reasoning_content
```

### 3.3 Inbound streaming response

```
SSE: data: { "choices": [{ "delta": { "reasoning_content": "..." } }] }
  -> StreamEvent::ReasoningDelta("...")  // yield
SSE: data: { "choices": [{ "delta": { "content": "..." } }] }
  -> StreamEvent::TextDelta("...")       // yield
SSE: data: [DONE]
  -> StreamEvent::Done                    // yield
```

### 3.4 Agent tool-call loop with reasoning

```
iteration 1:
  Provider returns Message {
    role: Assistant, content: "", reasoning_content: Some("plan: call tool X"),
    tool_calls: Some([call_1])
  }
  -> Agent appends whole message to history (reasoning preserved)
  -> Agent executes tool_calls, appends tool-result messages

iteration 2:
  Agent calls Provider again with full history.
  -> build_api_messages sees the iteration-1 assistant message:
     tool_calls.is_some() && reasoning_content.is_some()
     -> ApiMessage.reasoning_content = Some("plan: call tool X")  // REPLAYED
  -> Provider returns final answer Message (may itself have reasoning)
  -> Final answer's reasoning is preserved on the returned Message.

After the loop:
  Last assistant message (final, no tool_calls) has reasoning_content.
  On the *next* user turn (new conversation step), build_api_messages
  drops reasoning_content for this message because tool_calls.is_none()
  (DeepSeek-spec exact: text-only turns may drop reasoning_content).
```

### 3.5 Effort resolution (factory)

```
config.reasoning_effort = Some("max")           -> ("max",  auto_escalated=false)  // explicit wins
config.reasoning_effort = None, config.mcp = Some -> ("max",  auto_escalated=true)
config.reasoning_effort = None, config.mcp = None -> ("high", auto_escalated=false)
```

The resolved effort is **always** passed to `DeepSeekProvider::new`. Inside `DeepSeekProvider::new`, the effort is **only** applied via `with_reasoning(...)` when `is_reasoning_model(model)` is `true`. So a `deepseek-chat` model with `reasoning_effort = "max"` set in config receives the effort string through the constructor but discards it — no thinking-mode fields go on the wire.

### 3.6 SQLite round-trip

```
Outbound:
  Agent::complete returns Message { reasoning_content: Some(s), ... }
  -> CLI / Telegram code converts to StoredMessage { reasoning_content: Some(s), ... }
  -> SqliteStore::add_message INSERTs row including reasoning_content column.

Resume:
  SqliteStore::get_messages SELECTs reasoning_content as Option<String>
  -> StoredMessage { reasoning_content: Some(s), ... }
  -> conversion back to Message { reasoning_content: Some(s), ... }
  -> Agent feeds to provider.
  -> build_api_messages replays it iff the message also has tool_calls.
```

For pre-existing rows (column added via migration as nullable), `reasoning_content` reads as `NULL` -> `None`. Backwards compatible.

### 3.7 REPL render path

```
Agent::stream yields:
  ReasoningDelta(s) -> append to last DisplayMessage.reasoning buffer
  TextDelta(s)      -> append to last DisplayMessage.content buffer
  Done              -> finalize turn

build_history_lines (render.rs):
  for each DisplayMessage:
    if msg.reasoning.is_some() && cli.show_reasoning:
      render reasoning lines with Style::default()
        .add_modifier(Modifier::DIM | Modifier::ITALIC)
        prefixed with "▎reasoning: "
    render content with existing style
```

When `cli.show_reasoning = false`, REPL silently discards `ReasoningDelta` events (does not even buffer).

### 3.8 One-shot CLI (`synapse-cli/src/main.rs`)

```
TextDelta(s)      -> stdout (existing path)
ReasoningDelta(s) -> stderr (when cli.show_reasoning = true; default)
                  -> dropped (when cli.show_reasoning = false)
Done              -> stdout newline
```

This keeps stdout machine-readable for piped use (`synapse "..." | jq`) while preserving auditability by default.

### 3.9 Telegram send path

```
Agent::complete returns Message { content, reasoning_content }.

Persist:
  StoredMessage::new(...).with_tool_calls(...).with_reasoning(reasoning_content)
  -> SqliteStore::add_message  (regardless of show_reasoning flag)

Render outgoing:
  if !telegram.show_reasoning OR reasoning_content.is_none():
    body = md_to_telegram_html(content)
  else:
    let preview = synapse_core::text::truncate(
        reasoning_content,
        TELEGRAM_REASONING_PREVIEW_MAX_CHARS,
    );
    let preview = if preview.len() < reasoning_content.len() {
        // truncate already appended "..."; add explicit marker
        format!("{}[reasoning truncated]", preview)
    } else {
        preview
    };
    body = format!(
        "<blockquote>{}</blockquote>\n\n{}",
        format::escape_html(&preview),
        md_to_telegram_html(content),
    );

  chunk_html(&body) -> send chunks via ParseMode::Html
    (existing fallback to plain text on parse-mode rejection)
```

## 4. Non-Functional Requirements

| Requirement | How satisfied |
|-------------|---------------|
| Pre-commit gate | `cargo fmt --check && cargo clippy -- -D warnings && cargo test` after every task |
| No `unwrap()`/`expect()` in core | All new core code uses `?` propagation; serde and config validation return `ProviderError`/`ConfigError` |
| No blocking I/O in async | No new sync I/O introduced; reasoning rendering is in-memory |
| Hexagonal architecture | `synapse-core` exports new types; interface crates depend inward only |
| No `mod.rs` files | All additions follow Rust 2018+ layout (no new `mod.rs`) |
| 100-char line limit | Enforced by `cargo fmt` |

## 5. Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `thinking`/`reasoning_effort` leaks into OpenAI requests | Medium | High | `Option` fields with `skip_serializing_if`; only `DeepSeekProvider::new` ever calls `with_reasoning`. **Regression test:** assert `OpenAiProvider`-built request body contains neither field. |
| Forgetting tool-call history rule causes mid-conversation 400s | High | High | Encoded in `build_api_messages` gating logic + unit test `test_outbound_message_includes_reasoning_for_tool_calls` + integration test `test_agent_preserves_reasoning_through_tool_loop`. Documented prominently in `CLAUDE.md` and the research note. |
| Adding `ReasoningDelta` breaks exhaustive matches in REPL/CLI/Telegram | High (intentional) | Low | Add `#[non_exhaustive]` to `StreamEvent` (pre-1.0 is the right time); update every `match` site in the same task as the variant addition. Compile errors surface every site. |
| `Message` field addition breaks struct-literal callers | Low | Low | Codebase audit: struct literals are internal to `synapse-core` (tests, `complete_request`); update them in the same task. Pre-1.0 covers external break risk. |
| Effort `"max"` truncates answer when `max_tokens = 4096` | Medium | Medium | Document recommendation in README/CLAUDE.md (bump to 8192+ for `"max"`); deferred to follow-up for automatic floor. |
| Migration runs on a manually-patched DB | Low | Medium | sqlx tracks applied migrations in `_sqlx_migrations`. Fresh timestamp filename `20260510_004_*` ensures no hash collision. |
| REPL DIM style unreadable in some terminal themes | Low | Low | Style is a constant; user can rebuild. Future polish: configurable. |
| Telegram `<blockquote>` rejection on some clients | Low | Low | Already-vetted HTML subset (`format.rs`); existing plain-text fallback covers parse-mode rejection. |
| Reasoning content leaks to Telegram when `show_reasoning = false` | Medium | Medium | Render-path test asserts outgoing message contains no `<blockquote>` and no fixture reasoning text when flag is off. |
| Auto-escalation surprises a user who expected `"high"` | Low | Low | Tracing event with `auto_escalated = true` makes the choice observable; documented in `CLAUDE.md` factory section. |
| `REASONING_MODELS` drifts from DeepSeek's released list | High (over time) | Low | Single source of truth (`deepseek.rs`); mirrored in `docs/research/SY-22-deepseek-v4-pro.md`. Easy to amend. |
| MockProvider extension shape (option a vs b) | Low | Low | Plan picks option (b) — additive helper, no existing test churn. |
